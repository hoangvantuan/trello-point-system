## Mục tiêu workflow

Thực thi plan nhiều task (10+) nhanh, chính xác, không loop lại do lỗi type hoặc test.

## Trigger

Có plan đầy đủ với code spec sẵn, project dùng TypeScript strict + Vitest, task lõi thuần độc lập nhau.

## Trình tự (bản đồ)

1. **Đọc plan một lần, extract ALL task** — không để subagent tự đọc file plan (tốn context, dễ bỏ sót).
2. **Nhóm task cơ học vs task tích hợp:**
   - Task lõi thuần (không phụ thuộc SDK bên ngoài, code 100% có sẵn trong plan, verify bằng unit test) → **gộp vào 1 subagent**, truyền toàn bộ code.
   - Task SDK/UI (phụ thuộc nhau, verify bằng build) → **tách subagent riêng**, làm tuần tự.
3. **Subagent lõi thuần**: TDD từng file (test trước → FAIL → impl → PASS → commit). Sau đó `npm test` toàn bộ + `tsc --noEmit`. Báo cáo DONE_WITH_CONCERNS nếu phải thêm `!` để pass `noUncheckedIndexedAccess`.
4. **Verify sau subagent lõi**: tự chạy `tsc + npm test` thay vì tin báo cáo. Diagnostics LSP "Cannot find module" sau TDD là stale, không phải lỗi thật.
5. **Subagent SDK/UI**: dùng code chính xác từ plan, verify `npm run build` (tsc + vite build). Confirm dist sinh đủ file.
6. **Final code review** dùng model Opus: đọc toàn bộ diff, chạy test + build, tập trung vào XSS, logic biên, type consistency.

## Cạm bẫy / lưu ý

- **noUncheckedIndexedAccess**: subagent cần thêm `!` hoặc guard ở test fixtures — đây là sửa hợp lệ, không làm sai logic test.
- **LSP diagnostics stale sau TDD**: editor báo "Cannot find module" vì TDD tạo test trước src. `tsc --noEmit` thật mới là source of truth.
- **vite.config.ts/vitest.config.ts** nằm ngoài `tsconfig include` → LSP báo lỗi `__dirname`, `path` nhưng `tsc` không check chúng. Không cần sửa.
- **Không để subagent đọc file plan**: truyền full text qua prompt. Tránh context pollution và đảm bảo subagent nhận đủ code spec.
- **Commit riêng từng task**: dễ revert, dễ review, spec reviewer có SHA rõ ràng.
